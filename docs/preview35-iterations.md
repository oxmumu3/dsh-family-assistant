# 本轮迭代交付说明（0.2.0-preview.35 及之后）

这份文档只记录**已经上线到仓库 main、有测试覆盖**的能力与边界，避免把计划当成现状。

## 已交付

### 家人连接健康总览（⑥/⑤）

- `src/health.mjs`：逐人给出在线状态、最近收发时间、待发条数、近 24 小时失败/待核对/阻断分类，并给出「x/y 在线」这样一句话摘要。
- `status.health` 字段；工作台状态行与头部健康条直接展示，点家人可跳到本人详情。
- 不包含任何消息正文。

### 消息存储分片（③）

- 消息追加写入 `messages.log`（全量历史）。
- `family.json` 只保留每人最近 200 条热窗口，旧读取方与恢复路径无感；启动时合并去重。
- `compactMessages()` 可按人裁剪日志。
- 目录里因此会多一个 `messages.log`，涉及目录枚举的夹具已同步更新。

### 多账号传输层（②）

- `src/ilink/accounts.mjs`：显式注册、无默认账号、游标与 context token 按账号隔离；`snapshot()` 只报有无，不返回凭据。
- `clientFor(accountId)` 返回方法与 `src/weixin.mjs` 对齐、凭据绑定到账号的客户端，供通道或其它客户端复用。
- 插件内部通道仍走原发送路径：两条路径行为一致，切换收益低于回归风险，留待重写通道时采用。

### 迁移盘点（① 的前置）

- `src/member-native-migration.mjs`：只读盘点每位家人的旧工作区与任务账本，`prepared/queued/running/cancelling/needs_input/unknown` 视为未结清并阻塞切换。
- `status.migration` 影子字段；工作台显示「迁移就绪 / 迁移待处理」。
- 计划与灰度步骤见 `docs/member-native-migration.md`。

## 明确没做

- **家人侧切换宿主原生 agent**：需要先实现原生链路本体，并在真实家人对话上灰度验收；当前只做到盘点与状态展示。
- **工作台整页原生面板**：整页替换会打断语音桥与审批桥的挂载时序（实测 5 项测试失败，已回滚），改为在 iframe 内做原生信息层。
- 手机实际收到消息未验证；接口接受不等于送达。

## 验证方式

- 仓库 CI：`npm-release.yml` 的测试步骤覆盖锁、出站保留、提示词、作用域、工作台打包、健康、迁移盘点、传输层与微信协议。
- 全量本地套件：1251 项中 1247 通过，3 项失败为仓库既有问题（`rc1-owner-scope`、`member-agent` 两个 durable 恢复用例），与本轮改动无关，已在干净基线上复现。
